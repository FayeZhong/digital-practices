Week 02 · Digital Practices

Creating websites: returning to familiar ground

This reflection is a draft based on my workshop experience and the Week 2 teaching materials.

Starting again

In my third year as an undergraduate, I built a website about travelling in Singapore using HTML, CSS and JavaScript, with JSON for data. I therefore approached this workshop with some previous experience. Yet, after more than two years without regular practice, I found that my memories of the process had become muddled. Recognising a piece of code was not the same as understanding how to use it. Returning to the basics gave me an opportunity to rebuild that understanding rather than rely on familiarity.

Learning through a small problem

One difficulty was getting my CSS to appear in the browser. I needed to check whether the stylesheet had been saved, whether its filename matched the link in the HTML, and whether the page contained the elements targeted by the style rules. This made the relationship between structure and presentation more concrete. HTML organises the content, while CSS shapes how it is displayed; the browser needs the files to be connected correctly to bring them together.

The experience also reminded me that development involves checking apparently minor details. A page without styling did not necessarily mean that all the code was wrong. It meant that I needed to work through possible causes and understand which part of the process was not working.

Removing the stylesheet showed me that the headings, paragraphs and links remained, but the page fell back to the browser’s default presentation. Comparing this with the styled version helped me see how CSS shapes spacing, visual hierarchy and readability without changing the underlying content.

Putting the pieces together

This workshop helped me piece together what I remembered about making websites. The index.html file usually serves as the homepage, with HTML defining its content and structure. CSS controls the visual presentation, including colours, fonts, spacing and layout, and the stylesheet needs to be linked within the HTML file for those styles to appear. I also refreshed my understanding of the difference between viewing a webpage on my own computer and publishing it online. In this workshop, I used GitHub Pages to host my files so that other people could access the website through a URL.

Comparing ways of making

Comparing this process with CampusPress helped me understand the choices involved in website production. CampusPress provides a ready-made theme and editing interface, making it easier to add and update content. It does allow changes to pages, menus and some aspects of the layout, although the theme and available settings limit how much can be customised. Writing my own HTML and CSS gives me more control over the structure and appearance, but also means taking responsibility for the code and checking that everything works. This made the course’s idea of digital structures as constructed objects more tangible: both approaches involve design choices, but the tools shape which choices are available and how easily I can make them.

What I will take forward

I have chosen GitHub Pages for my portfolio because I want to refresh my coding skills and have more control over the design. That freedom also brings responsibility: I need to make sure the links work, the text is readable and the order of the reflections is clear. My next step is to develop a homepage with a card for each week, giving visitors a straightforward route into the entries. I want the portfolio to show how my understanding develops, as well as what I make.
